# CLAUDE.md

KusumaVision NMS — FTTH/GPON Network Management System (Laravel 12 + Vue 3/Inertia + Tailwind) owned by PT BERKAH MEDIA KUSUMA VISION (BMKV). A SmartOLT/NetNumen alternative for Indonesian ISPs to manage ZTE GPON OLTs (plus C-Data EPON/GPON & HiOSO EPON) and provision ONUs.

The user communicates in Indonesian — respond in Indonesian (bilingual when discussing code/English terms).

**Detailed developer docs live in `docs/handbook/`** (per-topic: overview, architecture, folder map, install/deploy, DB schema, routing, modules, SNMP/polling, CLI/telnet, alarm/Telegram, security/RBAC, frontend, troubleshooting, how-to-add-features). Start there for deep dives, and keep it in sync when structure or conventions change. License is MIT (`LICENSE`).

## Commands

```bash
composer dev        # serve + queue + pail logs + vite (concurrently)
php artisan serve --host=0.0.0.0 --port=8000
npm run dev         # vite
bash scripts/test.sh # PHPUnit — SELALU lewat skrip ini, JANGAN `php artisan test` polos (lihat Conventions)
npm test            # Vitest (tests komponen Vue di tests/js/*.spec.js; config vitest.config.js)
./vendor/bin/pint   # code style
php artisan telnet:proxy           # WebSocket<->telnet proxy daemon (browser terminal)
CGO_ENABLED=0 go build -mod=mod -trimpath -ldflags='-s -w' -o bin/kv-snmp-poller ./cmd/kv-snmp-poller   # rebuild Go SNMP poller (sama dgn install.sh; -mod=mod: vendor/ milik Composer)
sudo bash install.sh               # one-command deploy on a fresh Ubuntu server (--yes for non-interactive)
bash scripts/check-requirements.sh # verify tools/extensions/artifacts/services (+ min versions)
docker compose up -d --build       # "appliance" deploy: whole stack in containers on any PC (start.bat/start.sh 1-click); see docs/DOCKER.md
```

App DB is PostgreSQL (`kusumavision_nms`), Redis for cache/session/queue, locale `id`. Tests run on in-memory sqlite, so migrations must stay sqlite-compatible.

## Scope reality (important)

**C-Data & HiOSO modules are actively used** — features are requested on these pages too (e.g. port switcher, status cards & online/offline filter on `Pages/{CDataOlt,Hioso}/PortOnus.vue`, Okt 2026). Handle them carefully: CLI dialects differ per family **and** variant (C-Data EPON vs GPON verbs, HiOSO HA7304 vs HA7302), so only use OID/CLI syntax already verified live (`docs/SMARTOLT_CDATA_GUIDE.md`, `docs/SMARTOLT_HIOSO_GUIDE.md`) — unverified syntax stays off behind a capability, and there is no ONU registration/provisioning for these families. Shared pieces (`CDataOltScanner`, `PollOltJob::pollViaScanner`, `Components/CDataOlt/*`, `HiosoOltController` reusing C-Data components) must not regress the other family; don't refactor these modules opportunistically beyond the task at hand.

The PRD (`KusumaVision_NMS_PRD.md`) describes a broad vision; the **built scope is narrower**. Do not assume PRD features exist:

- **ZTE C300/C320/C600 supported** (plus non-ZTE C-Data EPON/GPON & HiOSO EPON, see Architecture). `App\Support\SmartOltSupport::driverKey()` returns `unknown` for anything else and disables all capabilities. **C600** (`SmartOltSupport::isC600()`, dikenali dari sysDescr **atau** sysObjectID `3902.1082.1001.600`) memakai subtree `.1082` (zxAccessNode) — tapi **cakupannya lebih sempit dari C300/C320**: tabel ONU di `.1082.500.20.2.1.2.1.*` (SN `.3`, model `.8`; phase-state kini dari `.1082.500.10.2.3.8.1.4` = 2 LOS/4 Working/5 DyingGasp/7 OffLine — menggantikan `.7` biner, set online identik 1343/1343; admin-state `.10.2.3.8.1.1` = 1 enable/2 disable; nama `.10.2.3.3.1.2`) dan **Rx ONU di `.1082.500.20.2.2.2.1.10`** (index `{ifIndex}.{onuId}.{onuPort}`, kembaran OID C300 `.1012.3.50.12.1.1.10` → berbagi parsing & skala; sentinel `65535`). Rx OLT-side (upstream, metrik **beda**) ada di `.1082.500.1.2.4.2.1.2` (milli-dBm, sentinel `-80000`) — belum dipakai. **Nama ONU, admin-state, phase kaya & unconfigured-discovery KINI terpetakan via SNMP** (Jul 2026, terverifikasi live): nama/deskripsi di `.1082.500.10.2.3.3.1.2/.3` — SNMP mengembalikan nama pelanggan asli WALAU CLI `show gpon onu detail-info` menyensor `Name`/`Description` jadi `********`; unconfigured di `.1082.500.2.2.11.2.1.2` (serial). Docs: `docs/ZTE_C600_Configured_ONU_Name_SNMP_Discovery.md`, `docs/ZTE_C600_Unconfigured_ONU_SNMP_Discovery.md`. Yang masih OFF: tulis (`supports_onu_toggle`/`supports_onu_info_write` = false untuk C600). **Penamaan CLI C600 = 3-tier `gpon_olt-1/{slot}/{port}` / `gpon_onu-1/{slot}/{port}:{id}` / `xgei-1/{slot}/{port}`** (terbukti dari running-config; asumsi 4-tier `gpon-olt_1/1/…` yang lama SALAH). **Provisioning C600 KINI ON** (`supports_provisioning=true`, Jul 2026): mode **Model B / SmartOLT TR069** via `ZteC600ProvisioningScriptBuilder` — struktur direproduksi persis dari running-config ONU asli (vport, dua service internet+mgmt, mgmt-ip in-band, VEIP/ACS, tr069-mgmt `tag pri`), `end` sebelum `write` (write invalid di config mode); pendukung: alokasi mgmt-IP otomatis (scan pool OLT, un-wrap IP terpotong line-wrap), dropdown ONU Type/T-CONT dari katalog, preset ACS dari OLT; WAN pppoe/dhcp/static **tetap ditolak** di C600. Yang masih OFF di C600: reconfigure/edit ONU (`supports_onu_config_write=false`). Kartu C600 nyata: GFGL/GFGM/GFGN (GPON 16-port), SFUB (uplink xgei). Semua terverifikasi live Jul 2026 — OID **tabel-ONU** lama (`.1082.500.10.2.3/.2.8/.2.11` sebagai tabel ONU) salah total & bikin C600 terbaca 0 ONU; tapi sub-tabel lain di subtree yang sama TERBUKTI benar & terpisah: `.10.2.3.3.1` (nama/deskripsi) dan `.10.2.3.8.1` (admin/phase). Referensi: `docs/SMARTOLT_ZTE_C600_GUIDE.md`.
- **SNMP read = v1/v2c only.** v3 throws (`OltSnmpClient`).
- **CLI execution = Telnet only.** `ZteCliProvisioningExecutor` rejects SSH (phpseclib installed but no SSH driver wired). Interactive browser telnet also Telnet-only (see Architecture).
- **No TimescaleDB, no `onus` table (per-OLT ONU state lives in the `last_test_result` JSON), no multi-vendor beyond the above, no AI** — these remain PRD vision, not code. RX history IS persisted though (`onu_rx_samples` raw samples, kept 3 days, sampled by `PollOltJob`; summarised hourly into `onu_rx_hourly` by `optical:aggregate-rx` and kept 45 days; `OnuRxSample::seriesFor()` picks the source per range; charted by `RxTrendCard`/`PortDetail`/`OnuDetail`).
- **Scheduled polling DOES use a Go engine** (`bin/kv-snmp-poller`, source `cmd/kv-snmp-poller/`) — see Architecture. On-demand actions (manual refresh, provisioning, telnet, per-port RX) are synchronous PHP in controllers/services — **except batch jobs**: copy-ONU-to-port (`app/Jobs/CopyOnusToPortJob.php` + `copy_onu_tasks`) and **bulk-enable-TR069** (`app/Jobs/Tr069BulkConfigJob.php` + `tr069_bulk_tasks`), both polled for progress.
- Per-OLT live state is cached as JSON in `snmp_olts.last_test_result`.

## Architecture

- `app/Models/SnmpOlt.php` — OLT inventory. Secrets (`snmp_read_community`, `snmp_write_community`, `cli_password`) use `encrypted` casts and are `$hidden`. On edit, empty secret fields preserve existing values (`withoutEmptySecrets`).
- `app/Services/Snmp/OltSnmpClient.php` — SNMP read: system info, GPON ports (IF-MIB), ZTE ONU table, unconfigured ONU discovery. Parsing quirks are tuned against real firmware (a production C320).
- `app/Services/ZteCliProvisioningExecutor.php` — Telnet session; auto-continues `--More--` pagers; masks CLI password in captured output.
- `app/Services/ZteProvisioningScriptBuilder.php` — builds ONU provisioning CLI scripts (register, VLAN/T-CONT, PPPoE/DHCP/static WAN, TR069, Remote ONT).
- `app/Services/ZteProfileCatalogService.php` — per-OLT profile sync; runs `show ...` commands and parses onu_type/tcont/vlan/ip profiles.
- `app/Services/ZteOnuRxPowerService.php` — ONU RX power via `show pon power onu-rx`.
- `app/Http/Controllers/SmartOltController.php` + `SmartOltProfileController.php` — all SmartOLT routes (`routes/web.php`, auth-protected). `onuMonitor()`/`refreshOnuMonitor()` back the cross-OLT **ONU Monitoring** page (route `monitoring.onu`, `Pages/SmartOlt/OnuMonitor.vue`): aggregates cached `port_onus` across all OLTs; refresh does one full-OLT SNMP walk and writes per-port cache. Per-port page (`Pages/SmartOlt/PortOnus.vue`) also has: **copy ONU config to another port** (batch — reads each source ONU's running-config in one telnet session, rebuilds a full registration via `ZteOnuReconfigureScriptBuilder::buildForCopy()`, queued job + progress modal), **delete ONU** (`no onu {id}`, gated `supports_onu_delete`). Halaman Unconfigured punya **Bind ONU** (ganti ONU rusak tanpa register ulang: `registration-method sn` di slot ONU lama port yang sama, `BindOnuModal.vue` → `smartolt.onu.replace`, gated `supports_onu_replace` = C300/C320 saja; terverifikasi live 29 Sep 2026, C600 belum — lihat guide ZTE §5.6a). Per-port refresh (`portOnusSnapshot`) walks only the port's ONU-table subtree on C300/C320 (scoped by `zteEncodeIfIndex` prefix) — not the whole OLT.
- **Go SNMP poller** — `cmd/kv-snmp-poller/main.go` (+ `go.mod`) builds to `bin/kv-snmp-poller`. `app/Services/Snmp/GoSnmpPoller.php` shells out to it (Symfony Process, JSON out); `enabled()` when `SNMP_POLLER_DRIVER=go` (`config/services.php`) and the binary exists. `app/Jobs/PollOltJob.php` (scheduled, runs under supervisor worker) uses the Go poller when enabled and **falls back to `OltSnmpClient`** on failure. Prod `.env` sets `SNMP_POLLER_DRIVER=go`.
- **Non-ZTE (C-Data & HiOSO) ikut scheduled polling** — `PollOltJob` mendeteksi family non-ZTE (`SmartOltSupport::isNonZte` = C-Data EPON/GPON **atau** HiOSO) lalu mengambil jalur scanner `pollViaScanner()`: scan penuh via `CDataOltScanner` (driver EPON SNMP / GPON SNMP tabel NSCRTV `17409.2.8.4` + enrich CLI opsional, menulis `last_test_result.port_onus` bentuk-ZTE; **status online GPON dari `onuOperationStatus` `.7`, JANGAN dari tabel optik `34592…21`** yang melaporkan ONU online sbg offline; FD1601S/FD1602S tak punya tabel `34592` sama sekali — lihat handbook 17), set penanda `ok` top-level (dibutuhkan `AlarmEvaluator`, scanner tak menyetelnya), catat sampel RX (`onu_rx_samples`) saat RX due, evaluasi alarm, log `PollingEvent`. `PollOltsCommand` (`olts:poll`, tiap menit) men-dispatch SEMUA OLT `polling_enabled` yang due (ZTE **dan** non-ZTE). On-demand refresh C-Data (`CDataOltController`) tetap ada untuk refresh manual/halaman. **Aksi write ONU C-Data** (EPON & GPON, via `CDataCliWriteService` — telnet `interface {epon|gpon} 0/{slot}`): rename `ont description`, reboot `ont reboot`, **enable/disable** (gated `supports_onu_toggle`, route `cdata-olt.onu.state`: EPON `ont enable|disable {port} {onuId}`, GPON `ont activate|deactivate {port} {onuId}` — **beda verb per-family**), **delete `ont delete {port} {onuId}`** (gated `supports_onu_delete`, route `cdata-olt.onu.delete`) — sintaks delete/rename/reboot identik EPON/GPON, terverifikasi help CLI live. **Remote ONT (GPON FlashV3 saja)**: buka/tutup akses web ONT dari WAN via `ont security-mgmt {port} {onuId} 1 state enable mode forward protocol web` (klon sintaks ZTE, TAK ada di manual resmi — ketemu via context-help live; push OMCI efek instan, dipatuhi juga ONT merk ZTE/F660) — `CDataCliWriteService::setRemoteAccess`, route `cdata-olt.onu.remote-access`, gated `supports_onu_remote_access` (V3 only); audit rule via `show current-config` (BUKAN `show running-config`). **Faceplate panel-depan**: `CDataFaceplateService` membaca IF-MIB (klasifikasi port PON/GE/XGE) + tabel device `17409.2.3.1.*` (model/serial/versi), di-cache `last_test_result.panel` oleh scanner, divisualkan `Components/CDataOlt/OltFaceplate.vue` di halaman Detail. **VLAN & detail port (firmware V3 GPON & EPON)**: halaman `cdata-olt.vlans` (lihat + buat VLAN + tag ke banyak port) dan `cdata-olt.port.detail` (GPON/EPON/GE/XGE: status, DDM + ambang OLT, statistik, VLAN, tag VLAN) lewat `CDataGponPortService` (nama warisan, melayani EPON juga; CLI telnet, deferred prop + cache cadangan) & `CDataGponPortController`; faceplate Detail membuka detail port untuk semua port. Gated `supports_cli_vlan`/`supports_cli_port_detail` = `SmartOltSupport::hasCDataV3Cli()` (sw_version faceplate `V3.`). Beda family: port GPON otomatis ikut VLAN baru & uplink Trunk; **EPON: uplink & port PON Hybrid (`vlan hybrid {p} tagged`), port PON harus di-tag manual, tak ada `show port info` di port EPON (→ `show port state`)**. Tag mengirim **gabungan** daftar lama + baru lalu verifikasi `show port vlan`; `show port ddm-info` hanya di mode `config`; interface dimasuki per slot (`interface xge 0/0`). Tulis = admin/operator/partner pemilik OLT (`canEditOltConnection`) + audit log, tanpa `save` otomatis. Referensi OID/CLI lengkap: `docs/SMARTOLT_CDATA_GUIDE.md` (§14 untuk VLAN/port).

HA7304)** — family non-ZTE ke-4. `SmartOltSupport::driverKey()` mengenalinya (`DRIVER_HIOSO_EPON`; needle `hioso|ha7304|25355`; V-Sol sengaja tidak dikenali — firmware beda, driver hanya teruji di HiOSO HA7304 4-port & HA7302 2-port) → `capabilities()` snmp_rx + rename/reboot/delete/enable-disable on (provisioning off). Rx valid tetap dipakai sebagai bukti pendukung online, tak pernah sebaliknya; nilai Rx lama dibawa `snmp_stale` maks `MAX_RX_NA_STRIKES` (2) poll lalu dikosongkan agar tak menampilkan angka redaman beku (`rx_na_strikes` per-ONU). Walk RX/Nama/link-state pakai `robustWalk` dgn **target-kelengkapan dari tabel MAC** supaya polling terjadwal di link lossy tak salah tandai ONU sebagai offline. **Anti-flap**: ONU yang tadinya online baru ditandai offline di snapshot setelah TERAMATI down beruntun `MAX_OFFLINE_STRIKES` (2) poll (`offline_strikes` per-ONU), supaya 1 pembacaan buruk tak bikin dashboard/faceplate (status port turunan jumlah ONU online) "berkedip" down/up — murni penghalus tampilan; gerbang alarm ada di debounce 2-poll `AlarmEvaluator`. Baris link-state & Rx yang sama-sama ABSEN dari walk = walk terpotong → pertahankan status terakhir. **Jangan walk** `25355.3.2.6.2.1.*` (puluhan ribu entry). **Punya controller + rute + halaman sendiri** (dipisah dari C-Data): `HiosoOltController` + rute `hioso-olt.*` + `Pages/Hioso/*` (Create/Edit/Detail/PortOnus + `Partials/HiosoOltForm`; reuse komponen presentasi `Components/CDataOlt/OltFaceplate`). Fault baru dicatat status **`AlarmEvent::STATUS_PENDING`** (belum dikirim, TAK tampil di UI/hitungan aktif — `AlarmController` web+API filter `whereIn active,cleared`; bell/dashboard/Telegram-count pakai `STATUS_ACTIVE`). Notifikasi raise baru dikirim bila fault **masih ada di poll berikutnya** (promote PENDING→ACTIVE); bila pulih sebelum konfirmasi, baris pending **dihapus diam-diam** (tak ada notif down maupun clear). `openAlarms()` ambil ACTIVE+PENDING; deteksi transisi (port/onu/rx/unreachable) pakai keduanya. Interval poll umum 5 mnt → alarm sungguhan datang ~2 poll (~10 mnt).
- **Korelasi root-cause (anti alarm-storm)** — `AlarmEvaluator` menahan banjir alarm anak, saklar `alarm_settings.suppress_child_alarms` (Settings → Alarm, default ON): (1) OLT unreachable (`snapshot.ok=false`) → port & ONU tak dievaluasi sama sekali; (2) sebuah PON **port down** mensupres alarm ONU-offline/LOS/dying-gasp **baru** untuk ONU di port itu (himpunan `$downPorts` "slot/port"), pesan port-down menyebut jumlah ONU terdampak (`meta.affected_onus`); (3) **SEMUA ONU satu ODP offline** (≥2 ONU, port induknya masih up) → satu alarm **`odp_down`** (scope `odp`, severity major, signature `odp:{id}:odp_down`, `meta.odp_id/odp_name/affected_onus`), alarm ONU anggotanya disupres — status per-ODP dihitung `OdpAlarmGrouper::statuses()` dari snapshot (`total` = ONU ODP yang muncul di snapshot, `down` = yang offline). Episode ONU yang **sudah terbuka** saat induknya turun tetap direkonsiliasi (dijaga `onuHasStateAlarm`) supaya tak ter-clear palsu, tapi ditandai **`meta.notified=false`** → notifikasi raise **dan** clear-nya dilewati (kalau tidak, pemulihan port/ODP = banjir pesan "cleared"); begitu induknya pulih & ONU masih mati, tanda dilepas dan alarm dikirim sebagai gangguan mandiri (`$parentRecovered` juga membuka ONU yang tak punya transisi online→offline karena matinya tertutup gangguan induk). ODP yang gangguannya terlanjur tercatat per-ONU diangkat sekali jadi satu `odp_down` (`$hasOpenChildren`) agar pemulihannya punya induk yang melapor. ODP yang **sebagian** ONU-nya down tetap dirangkum di layer notifikasi jadi 1 pesan (`OdpAlarmGrouper::group()`, saklar `group_odp_alarms`; grup juga berlaku untuk pesan pemulihan). Interpretasi kode `last_down_cause` ke bahasa Indonesia di UI: `resources/js/lib/onu.js` (`lastDownCauseLabel`).
- **Pengaturan alarm TERPUSAT (Settings → tab Alarm)** — `alarm_settings` (model `AlarmSetting`) satu-satunya sumber kebijakan alarm: `confirm_before_notify` (debounce 2 poll vs realtime), `min_severity`, `notify_on_raise`, `notify_on_clear`, `notify_types` (null = semua jenis), `suppress_child_alarms`, `group_odp_alarms`. `TelegramSetting` (bot global) & `FcmSetting` **mendelegasikan** `minSeverityRank()`/`notifyTypes()`/`shouldNotifyType()`/`notifyOnRaise()`/`notifyOnClear()` ke situ; kolom senama di kedua tabel kanal dipertahankan tapi TAK dipakai lagi (rollback-safe), dan endpoint `settings.telegram.update`/`settings.fcm.update` tak lagi menerima field filter — tab kanal cuma koneksi (token/chat id/webhook, saklar push, daftar perangkat). **Bot partner (`PartnerTelegramBot`) tetap punya filter sendiri** (diatur partner di halamannya).

## Conventions

- **Test SELALU lewat `bash scripts/test.sh`** (alias `composer test`), **jangan pernah** `php artisan test` / `phpunit` polos. Checkout ini melayani produksi, dan `bootstrap/cache/config.php` dimuat lebih dulu saat boot lalu **menang** atas `<env>` di `phpunit.xml` — koneksi resolve ke pgsql `kusumavision_nms` walau `DB_CONNECTION=sqlite` sudah diset (terukur 10 Agu 2026). 66 file test memakai `RefreshDatabase` (5 Okt 2026) → `migrate:fresh` pada koneksi default = **drop seluruh tabel produksi**. Skrip itu mengalihkan `APP_CONFIG_CACHE`+`APP_ROUTES_CACHE` ke path non-eksisten (hanya dua ini — `APP_SERVICES_CACHE`/`APP_PACKAGES_CACHE` ditulis ulang saat boot, path tak-writable = exception) lalu **abort** kecuali probe menghasilkan `sqlite|:memory:`. `config:clear` **bukan** solusi: DB aman tapi cache config produksi terhapus permanen. Baseline hijau (5 Okt 2026): 676 passed / 4077 assertions, `npm test` 50 passed; `flutter test` 27 passed (28 Sep 2026).
- Provisioning writes an audit row in `smartolt_onu_registrations` (script generated first, executed later/optionally). Profiles are scoped per-OLT with global (`snmp_olt_id = null`) fallback.
- `SMARTOLT_ZTE_C300_C320_C600_GUIDE.md` is the **authoritative ZTE CLI command reference** — consult it over guessing command syntax. Untuk **C600** pakai `docs/SMARTOLT_ZTE_C600_GUIDE.md` (guide lama bagian C600 pernah salah total). **OID vendor hanya boleh masuk kode setelah dibaca dari perangkat asli** — kalau tak bisa diverifikasi, biarkan `null` dan matikan capability-nya. PDF C600 di `docs/*.pdf` **tak terverifikasi**, jangan dipakai sebagai sumber OID.
- `WORKLOG.md` logs work phase-by-phase (Created/Changed/Notes, with real-OLT verification). Add a matching entry for meaningful changes.
- **Seluruh string user-facing dwibahasa ID/EN** (default `id`): frontend via vue-i18n `$t('ns.key')` (`resources/js/lang/{id,en}.json`, ~44 namespace; custom messageCompiler = literal + `{param}` saja, TANPA linked/plural), backend via `__()` (`lang/{id,en}/` — `flash.php` untuk flash controller, `reports.php` ikut CSV/PDF, `validation/auth` ID). Fitur baru WAJIB menambah key ke **kedua** bahasa; opsi ber-enum stabil diterjemahkan frontend by-key (`lib/alarm.js`); switch bahasa: `LanguageSwitcher` + middleware `SetLocale` + kolom `users.locale`. **Pesan error/status backend** (exception, `abort`, `'message'`/`'error'` JSON, `->with()`, pesan validasi kustom) **JANGAN ditulis literal** — pakai `__('grup.kunci', [...])` di grup per domain `lang/{id,en}/{olt,zte,cdata,hioso,odp,common}.php` (issue #1: tampilan English masih menampilkan error Indonesia). Teks `id` identik dgn teks lama (test berjalan locale `id`); `APP_FALLBACK_LOCALE=en` → kunci yang lupa ditaruh di `lang/id` diam-diam tampil Inggris, jadi dijaga `tests/Unit/LangParityTest` (kunci & placeholder id=en, setiap `__('g.k')` literal di app/ ada di kedua bahasa). **Sengaja tetap Indonesia**: teks yang disimpan/diantrekan sebagai data (pesan alarm, push FCM, item progres task salin-ONU/TR069, error backup config, deskripsi `AuditLogger`) dan log. Daemon `telnet-proxy` tanpa `SetLocale` → memakai `users.locale` pemilik tiket per koneksi.
- **UI/tema dashboard** (dark glass, aksen cyan/sky, kelas `kv-*` di `resources/css/app.css`, shell `AuthenticatedLayout`) — **dua tema** Gelap/Terang/Ikuti sistem: semua ramp warna Tailwind = CSS custom property per `[data-theme]` (`tailwind.tokens.mjs`, nilai di `app.css`), `App\Support\Theme` (kolom `users.theme` → cookie `kv_theme` tak terenkripsi → gelap), simpan lewat `PATCH profile.theme` → 204; aturan kelas (`text-onaccent`, `bg-canvas-3`, `kv-terminal`, `kv-surface`) di `UI_DESIGN_SYSTEM.md` §3a–3b: saat menambah/ubah halaman atau komponen, ikuti aturan di `docs/handbook/15-ui-tema-dashboard.md` (pakai `kv-*` dulu, kartu kaca semi-transparan, tabel responsif desktop+mobile, ikon Lucide, gerbang `auth.can`, string Indonesia).
- Live test OLTs: id=1 (a C320) and id=2.
- **Prod runs cached config** (`bootstrap/cache/config.php`); `.env` is `640 root:www-data` so the app user can read it. After any `.env`/config change run `php artisan config:cache` so the cache picks it up, then restart the supervisor daemons (`queue:restart` for `kusumavision-worker`, `supervisorctl restart kusumavision-telnet-proxy`). Long-lived daemons need a restart to pick up code changes. (Keep `.env` group-readable by `www-data` — if it's `root:root`, a cleared config falls back to sqlite and the site 500s.)
- **Fresh-server deploy** is automated by `install.sh` (installs runtime, DB, `.env`, build, Go poller, migrations, nginx site + supervisor daemons `kusumavision-worker`/`-scheduler`/`-telnet-proxy`). `scripts/check-requirements.sh` validates tools/extensions/services. Full walkthrough: `docs/handbook/04-instalasi-deploy.md`.
- **Docker "appliance" deploy** (install lengkap di 1 PC seperti NetNumen, buat dibagikan ke banyak lokasi) — `Dockerfile` (multi-stage: node build → `public/build`, go build → `bin/kv-snmp-poller`, php:8.3-fpm + nginx + supervisor) + `docker-compose.yml` (service `app` all-in-one, `db` postgres:16, `redis` redis:7; volumes `pgdata`/`redisdata`/`app_storage`). Konfig di `docker/` (`nginx.conf`, `supervisord.conf` = daemon sama seperti install.sh, `entrypoint.sh`, `php.ini`). `entrypoint.sh` menyiapkan storage skeleton (volume mask), **auto-generate & persist `APP_KEY`** di volume bila kosong, `migrate --force`, admin opsional (`ADMIN_*`), `optimize`, lalu exec supervisord. Env runtime dari compose (bukan file `.env` Laravel); user tune via `.env` host-side (`.env.docker.example`). Launcher 1-klik `start.bat`/`stop.bat`/`update.bat`/`start.sh`. **Tak ada perubahan kode app** — paritas fungsional dengan `install.sh`. Panduan operator `docs/DOCKER.md`, arsitektur `docs/handbook/18-docker-appliance.md`.
